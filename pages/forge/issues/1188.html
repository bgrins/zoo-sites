Quote latency spikes at window rollover #1188

Open m.calderwood opened this issue on 22 June · 1 comment
All issues4 #1188
m.calderwood opened this issue on 22 June

p99 quote latency climbs from about 140 ms to 1.8 s for roughly thirty seconds after each 15-minute boundary. The gateway reads the tariff table once per request, and at a boundary every lane asks for the new window's rate at once.

The tariff table itself is fine: it serves the burst, just slowly. A per-window cache in the gateway would turn thousands of reads per boundary into one per lane and class.

r.vandermolen commented on 23 June

Agreed on caching per lane, class and window. Keep the TTL no longer than the window so a cached price can never outlive the window it was priced in.
