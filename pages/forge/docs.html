Documentation

How review, pipelines and the registry work on Kettleforge. For anything not covered, write to support@kettleforge.example.
Reviewing a pull request

Open the Files changed tab and use the plus button in a line's gutter to write a comment on that line. Comments are staged, not published, until you submit the review with a summary and a verdict: Comment, Approve or Request changes. A repository can require a code owner's approval before Forge merge is enabled.

You can submit more than one review. The latest verdict from each reviewer is the one Merge status shows.

Anvil pipelines

A pipeline runs on every push, from the definition in .anvil/. Jobs a repository marks as required block Forge merge while they fail. Open a failing job from the pull request's Checks tab to read its output.

Registry

Pipelines publish container images and npm packages to the repository's registry. Each version records the pipeline and commit that built it, so an artefact can be traced back to its source.

Tokens and access

Access tokens are scoped to repositories and expire on a date you choose. A token is shown once when it is created; store it then. See security for how tokens found in public repositories are revoked.
