Documentation

The short version of how Cindergrid runs your deployments. Anything not answered here goes to support.

Runs and steps

A run is one attempt to take a commit to an environment. Steps execute in a fixed order - checkout, build/image, scan/deps, push/registry, migrate/schema, release/gate, rollout/canary, notify/webhook, diagnostics, cleanup/artifacts - and a failed step stops everything after it except diagnostics and cleanup, which always run. The step summary on the run page shows each step's outcome; the run log carries the full line-by-line record, searchable from the toolbar or downloadable as a raw text file.

Release gates

Production promotions are evaluated against a release policy (currently release-prod-v4). Rules cover the change window, recorded approvals, scan findings and image provenance. A denied rule fails the release/gate step and the run; the log states which rule denied promotion and why. Gates are policy, not advice - there is no override button in the console.

Secrets

Org-level secrets are injected as environment variables at step start and are write-only after creation. See the Secrets tab for names, rotation schedules and the steps that consume each one.

Logs and retention

Run logs and support bundles are retained for fourteen days from the end of the run. The raw log is a plain-text document linked from the run page toolbar; the viewer's search runs server-side over the same lines. Older material lives in the archive and is restored on request through support.
