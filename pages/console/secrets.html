Secrets

Org scope

Secrets are injected into run steps as environment variables at step start. Values are write-only: a value is shown once when it is set and can never be read back, only replaced. Rotation is enforced on the schedule below.

Organisation secrets

REGISTRY_PUSH_TOKEN **************** rotated 2026-02-14, due 2026-05-14 push/registry
ATTESTATION_SIGNING_KEY **************** rotated 2026-01-02, due 2027-01-02 release/gate, key ring release-2026
SCHEMA_MIGRATOR_DSN **************** rotated 2026-03-01, due 2026-06-01 migrate/schema
NPM_MIRROR_READ_TOKEN **************** rotated 2025-12-19, due 2026-12-19 build/image
WEBHOOK_HMAC_SECRET **************** rotated 2026-02-28, due 2026-08-28 notify/webhook

Rotation policy

Tokens with registry or database reach rotate every ninety days; signing keys rotate yearly and re-sign nothing retroactively. A secret past its due date blocks new production runs until it is replaced. Runner leases are separate from these values and renew automatically (the current lease is visible in any run's diagnostics section).

Only organisation administrators can set or replace a value. Replacing a secret takes effect on the next run; running steps keep the value they started with.
