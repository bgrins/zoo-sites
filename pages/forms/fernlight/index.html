Fernlight Atlas 3

Field mapping and survey tooling for small crews.

Atlas 3 is the third generation of our desktop mapping client, written for the two- and three-person crews who do the measuring themselves and cannot afford a day lost to software. It reads what your instruments already produce, keeps working when the signal drops, and hands your projects back in a format you can open without us.

Atlas 3 is in private beta — join the waitlist

Seats are released in weekly batches. The programme terms govern every request and every seat; read them in full before you apply.

What Atlas 3 does

A project in Atlas 3 starts from raw observations rather than from a drawing. Import total-station and GNSS files as they come off the instrument, let the code table turn point codes into layer styles, and work the result up into the deliverable your client asked for. Codes the table does not recognise are held on a review layer, so a mislabelled shot surfaces as a question instead of quietly disappearing.

Direct instrument import

Observation files load unmodified, with antenna heights and units read from the file rather than typed in again.

Offline by design

Once a workspace has synced, the client runs without a connection and reconciles when the crew is back in range.

Portable projects

Interchange export writes geometry, raw files and a checksummed manifest to one archive that re-imports losslessly.

Built around the crew, not the office

Workspaces hold projects, base layers and invitations together, and one workspace key authenticates one workspace. Invite colleagues from the console instead of passing the key around; a lost key can be rotated the same day, which is faster than untangling who else had it. Tile service, base layers and backups all live in the region chosen when the workspace is created, and nothing moves regions without notice.

Diagnostics are deliberately dull. atlas doctor reports GPU support, disk headroom and connectivity in one pass, which is the first thing to run when a machine on site behaves differently from the one on the desk.

The current build

Release candidates go out to the beta cohort every few weeks, and every change that reaches a build is written up. The changelog carries the release notes for the private beta, and the documentation covers installation, workspace keys, survey import, interchange export and telemetry settings.
