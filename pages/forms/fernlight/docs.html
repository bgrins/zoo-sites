Atlas 3 documentation

Field mapping and survey tooling for small crews.

Getting started

When your seat opens we email an install link and a workspace key. Run the installer, then activate with atlas auth login --key and the key we sent. The client works offline once a workspace has synced; the first sync pulls your base layers and can take a few minutes on slow links.

The atlas doctor command checks GPU support, disk headroom, and connectivity, and is the first thing to run if anything looks wrong.

Workspaces and keys

A workspace holds projects, base layers, and crew invitations. One key authenticates one workspace; invite colleagues from the console rather than sharing the key itself. If a key is lost, write to the beta address and we rotate it — the old key stops working immediately.

Survey import

Atlas 3 imports total-station and GNSS observation files directly. Drop files onto an open project or use atlas import with a path. Point codes map to layer styles through the code table in project settings; unmatched codes land on a review layer instead of being dropped.

Interchange export

Every project can be exported at any time in the documented interchange format: a zip archive holding geometry as line-delimited JSON, raw observation files unmodified, and a manifest with checksums. Exports are self-contained and re-import losslessly, so they double as archival snapshots.

Telemetry settings

The beta client reports crash traces, timing samples, and feature usage counts. Under settings, telemetry can be set to full or reduced; the reduced level drops timing samples and usage counts but keeps crash traces for the duration of the beta. Payloads are viewable locally with atlas telemetry show before they are sent.
